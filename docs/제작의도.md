# 제작 의도 — 운명원 댓글 에이전트

## 한 줄 요약
"광고처럼 보이는 순간 실패한다"는 전제에서 출발했습니다. 그래서 AI가 **그 영상에서만 나올 수 있는 말**을 하게 만들고, 지켜야 할 규칙은 프롬프트가 아니라 **코드로 강제**했습니다. 그리고 사람이 결과를 눈으로 확인하며 쓸 수 있도록 **리허설 → 리얼** 순서와 **화면에 보이는 자동화**를 기본으로 설계했습니다.

## 1. 왜 '장면 짚기'를 가장 앞에 두었나 (맥락 이해)
홍보 댓글이 실패하는 가장 흔한 이유는 어느 영상에 붙여도 되는 일반적인 문장이라는 점입니다. 시청자는 그런 댓글을 바로 알아보고 넘기거나 신고합니다.

- AI는 댓글을 쓰기 전에 **① 영상 속 연애 고민 한 줄**과 **② 짚을 장면(자막 원문 + 타임스탬프)**을 먼저 정리합니다. 이 두 가지가 화면 ② 칸에 그대로 보여서, 사람이 AI의 이해가 맞는지 바로 검토할 수 있습니다.
- 자막이 없으면 제목, 설명, 인기 댓글로 대신합니다. 인기 댓글은 말투를 맞추는 데만 쓰고 문장을 베끼지 않게 했습니다.
- 검사기는 댓글이 장면의 대사와 3글자 이상 겹치는지, 또는 장면 핵심어를 담았는지 확인합니다. "4분쯤 대사"처럼 **시간만 있고 내용이 없으면 장면 언급으로 인정하지 않습니다.** 초안에서는 장면과 겹치는 부분에 밑줄이 그어집니다.
- 이전에 단 댓글과 두 글자 단위 유사도가 45% 이상이면 막습니다. 그래서 영상마다 다른 댓글이 나옵니다.

## 2. 운명원으로 자연스럽게 넘어가는 구조 (유도)
댓글 흐름을 **장면에 공감 → 나의 평범한 연애 경험 → "결국 인연이나 타이밍은 따로 있나" → 운명원 연애사주가 궁금하다**로 고정했습니다.

- 심리 분석, 연애 기술, 재회 방법 같은 영상은 대부분 "노력해 봐도 모르겠다"는 감정으로 끝납니다. 이 감정이 사주를 보고 싶어지는 지점과 맞닿아 있어서, 그 연결을 댓글 안에서 만들어 줍니다.
- 운명원은 **'잘 본다고 들은 곳'**으로만, **정확히 한 번** 언급합니다. 이용해 본 것처럼 쓰는 지어낸 후기("봤는데", "다녀왔는데", "맞더라")는 과제 금지사항이자 실제 운영에서 허위 후기 위험이라 코드로 막았습니다.
- "강추", "지금 바로" 같은 광고 말투, 링크, 해시태그, @멘션, 같은 말 반복도 막습니다.
- **말투(페르소나) 5종**을 두었습니다. 영크크(20대 반말·신조어), 늙크크(30~40대 자조 유머), 센스쟁이(재치 있는 비유), 똑순이(요점 정리형 존댓말), 매너남(정중한 남성 시점)입니다. 기본값 **자동**은 영상의 시청자층에 맞는 말투를 AI가 고르고, 최근에 쓴 말투는 피해서 여러 댓글이 한 사람이 쓴 것처럼 보이지 않게 합니다.

## 3. 규칙은 프롬프트가 아니라 코드로
LLM은 지시를 가끔 어기고, 글자 수를 잘 세지 못합니다. 그래서 네 겹으로 막았습니다.

1. **후보 3개 중 선택**: 한 번에 길이가 다른 후보 3개(약 70·90·105자)를 받아, 필수 규칙을 모두 통과하면서 장면을 짚은 후보를 고릅니다.
2. **다시 쓰기**: 후보가 모두 어긋나면 어긋난 항목(예: "120자 초과(125자)")을 알려 주고 최대 3번까지 다시 쓰게 합니다.
3. **화면 단계**: 사람이 직접 고쳐도 0.35초마다 다시 검사합니다. 필수 항목이 실패하면 [댓글 달기]가 잠기고, 이유가 버튼 아래에 나옵니다.
4. **서버 단계**: 게시 API가 마지막으로 다시 검사합니다. 화면을 우회해도 통과하지 못합니다.

| 검사 | 기준 | 필수 |
|---|---|---|
| 길이 | 40~120자(공백 포함) | ✔ |
| 브랜드 | "운명원" 정확히 한 번 | ✔ |
| 반복 | 같은 말(4글자 이상)이 3번 이상이면 차단 | ✔ |
| 링크·해시태그 | URL, 도메인, #태그, @멘션 금지 | ✔ |
| 지어낸 후기 | 이용해 본 것처럼 쓰는 표현 금지 | ✔ |
| 중복 | 이전 댓글과 유사도 45% 미만 | ✔ |
| 장면 언급 | 대사·핵심어를 실제로 짚었는지 | 경고 |

## 4. 운영 규칙과 안전장치
| 규칙 | 구현 |
|---|---|
| 영상당 댓글 1개 | 게시 완료, 진행 중, **게시 버튼은 눌렸지만 확인에 실패한 경우**까지 모두 그 영상을 잠급니다. 중복 게시가 계정에 가장 위험하기 때문입니다. |
| 한 영상엔 계정 하나 | 잠금이 계정과 상관없이 영상 단위로 걸립니다. 전체 자동에서도 서버가 같은 규칙으로 막습니다. |
| 하루 상한(기본 10) | 한국 시간 자정 기준으로 셉니다. 진행 중인 것도 포함하며, 전체 자동은 남은 수까지만 고를 수 있습니다. |
| 동시에 하나만 | 게시가 끝나기 전에는 다음 게시를 받지 않고, 같은 크롬 프로필을 두 번 열지 않습니다. |
| 계정 자동 배정 | 로그인이 확인된 계정 중 오늘 적게 쓴 계정 → 가장 오래 전에 쓴 계정 순으로 돌아가며 씁니다. |
| 시작은 항상 리허설 | 켤 때마다 리허설(입력까지만, 게시 안 함)로 시작합니다. 리얼은 사람이 확인한 뒤에만 켜집니다. |
| 기록 | 시간, 영상, 계정, 말투, 댓글, 결과, 실패 이유, 캡처, 댓글 링크를 남기고 CSV로 내보냅니다. |
| 비정상 종료 | 서버가 꺼질 때 '진행 중'이던 기록은 '확인 필요'로 바꿔 잠가 둡니다. |

## 5. 사용성 — 설명 없이 쓸 수 있게
- 화면을 왼쪽부터 **① 영상 불러오기 → ② 영상 선택 → ③ 댓글 달기** 순서로 놓고, 강조색은 [댓글 달기]에만 썼습니다.
- 버튼이 잠기면 이유를 문장으로 보여 줍니다(예: "이미 유튜브2 계정으로 댓글을 단 영상이에요").
- 게시 과정은 5단계(프로필 열기 → 댓글 창 찾기 → 한 글자씩 입력 → 게시 → 내 댓글 확인)로 보여 주고, 입력 중에는 몇 글자까지 쳤는지 실시간으로 표시합니다.
- **리허설 → 리얼**: 리허설이 성공하면 "리얼 모드로 바꾸고 바로 게시 / 리얼 모드로만 바꾸기 / 리허설 계속"을 묻습니다. 상단 배지(노랑=리허설, 빨강=리얼)로 지금 모드를 항상 알 수 있습니다.
- **크롬이 대시보드 앞에**: 게시하는 동안 크롬 창을 팝업 크기로 대시보드 앞에 띄워서, 입력·게시·확인 과정과 ③ 칸의 진행 상황을 한 화면에서 볼 수 있습니다.
- **▶ 전체 자동(E2E)**: 버튼 하나로 영상 불러오기 → 선택 → AI 초안 → 자동 배정 → 게시를 영상마다 반복합니다. ①②③ 칸이 실제로 움직이고, 상단 막대에 "2 / 3"과 지금 단계, [중단]이 보입니다. 이미 단 영상, 댓글 사용 중지, 규칙 미통과는 건너뛰고, 영상 사이에는 8~15초를 둡니다.
- **계정 클릭 → 유튜브 열기**: 계정을 누르면 그 크롬 프로필로 유튜브를 별도 창으로 열지 묻습니다. 계정 상태를 직접 확인할 때 씁니다.

## 6. 기술 선택
- **크롬 프로필**: 평소 쓰는 기본 프로필은 자동 제어가 막혀 있어서, `profiles/유튜브N` 폴더를 user-data-dir로 쓰는 전용 프로필을 Playwright `launchPersistentContext`로 엽니다. 구글 로그인은 자동 제어가 아닌 **일반 크롬 창**에서 사람이 직접 합니다.
- **사람처럼 입력**: 글자마다 70~170ms 간격을 랜덤으로 두고 문장부호 뒤에서는 조금 더 쉽니다. 게시 전에 입력된 글이 초안과 같은지 비교해 다르면 게시하지 않습니다.
- **창 맨 앞 띄우기**: Windows는 백그라운드 프로그램이 연 창을 뒤에 깔기 때문에, 게시 중에만 크롬 창을 '항상 위'로 올리고 끝나면 해제합니다.
- **YouTube 데이터**: 키 없이도 동작하도록 유튜브 웹 내부 API로 검색과 인기 댓글을 읽고, `YOUTUBE_API_KEY`가 있으면 공식 Data API v3를 씁니다. 자막은 플레이어의 자막 트랙을 읽습니다.
- **AI**: Gemini, Claude, OpenAI 중 키가 있는 것을 씁니다. 무료 Gemini는 사용량이 몰리면 거절(503)하는 경우가 많아, 막히면 다음 모델로 자동 전환하고 마지막으로 성공한 모델을 먼저 씁니다.

## 7. 검증
- 규칙 자체 점검 10건(정상 통과, 짧은 글·링크·해시태그·지어낸 후기·브랜드 누락·브랜드 2번·반복 스팸·중복 차단, ㅋㅋ 허용)을 모두 통과했습니다.
- 실제 영상으로 초안을 만들어 보니, 후보 3개 방식을 적용한 뒤에는 대부분 첫 시도에 규칙을 통과했습니다(영상당 약 5초).
- 리허설로 크롬 열기 → 댓글 창 찾기 → 한 글자씩 입력 → 지우기를 반복 확인했고, 화면 캡처로 크롬이 대시보드 앞에 뜨는지 확인했습니다. 전체 자동은 리허설 2건(계정 유튜브2 → 유튜브3 자동 배정)으로 확인했습니다.
- 만들면서 발견해 고친 실제 문제: 모드 배지가 리얼인데 리허설로 보이던 표시 버그, 확인 전 계정을 자동 배정하던 문제, 규칙을 통과한 반복 스팸 문구, 크롬 창이 대시보드 뒤에 깔리던 문제.

## 8. 실제 운영으로 넘어간다면 (PM 관점의 위험)
- **광고 표기**: 공정위 「추천·보증 등에 관한 표시·광고 심사지침」은 경제적 대가를 받은 추천이라면 그 사실을 밝히도록 정합니다. 실제 캠페인에서는 브랜드가 공식 계정으로 참여하거나 대가 관계를 표기하는 방식을 함께 설계해야 한다고 봅니다.
- **플랫폼 정책**: 여러 계정으로 같은 업체를 언급하면 유튜브 스팸 정책에 걸릴 수 있습니다. 그래서 하루 상한, 영상당 1개, 영상마다 다른 문장과 말투, 사람 속도의 입력과 간격을 기본값으로 두었습니다. 운영 지표로 **댓글 노출 유지율**(며칠 뒤에도 보이는지)을 따로 추적해야 합니다.
- **성과 측정**: 다음 단계로 댓글별 좋아요·답글 수를 다시 수집하고, 운명원 쪽에 유입 경로 질문을 넣어 어떤 영상 유형·말투·문장 구조가 효과적인지 학습시키는 방식을 생각하고 있습니다.
